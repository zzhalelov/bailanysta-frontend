# Bailanysta — Социальная сеть с AI-ассистентом

**Bailanysta** (каз. «В связи» / «Связь») — полнофункциональное веб-приложение социальной сети с поддержкой AI-генерации контента, кастомным национальным оформлением и интерактивными социальными функциями.

Проект объединяет публикацию контента, подписки, лайки, комментарии, профили пользователей и AI-ассистента для генерации постов в едином адаптивном интерфейсе.

## Возможности

### Лента публикаций

- Просмотр всех публикаций пользователей.
- Персональная лента **«Мои подписки»**.
- Отображение автора, текста и времени публикации.
- Динамическое обновление содержимого.
- Возможность взаимодействия с публикациями.

### AI-генератор постов

В приложение встроен AI-ассистент на базе **Gemini**, который позволяет:

1. Открыть модальное окно AI-генератора.
2. Ввести текстовый промпт.
3. Отправить запрос AI.
4. Получить сгенерированный текст.
5. Автоматически вставить результат в форму создания публикации.
6. При необходимости отредактировать текст перед публикацией.

Это позволяет быстро создавать контент непосредственно из интерфейса социальной сети.

### Социальные взаимодействия

Пользователи могут:

- ставить лайки;
- оставлять комментарии;
- подписываться на других пользователей;
- отменять подписку;
- просматривать профили;
- видеть статус подписки;
- взаимодействовать с публикациями непосредственно из ленты.

Комментарии и публикации сохраняют дату и время создания.

### Multi-User Switch

Для демонстрации и тестирования социальной логики реализовано быстрое переключение между пользователями.

Пользователь может выбрать другой аккаунт непосредственно из Navbar без необходимости выполнять logout/login.

Это особенно удобно при тестировании сценариев:

- пользователь A подписывается на пользователя B;
- пользователь B публикует пост;
- пользователь A ставит лайк;
- пользователь B проверяет комментарии;
- проверяется персональная лента подписок.

### Управление публикациями

Автор публикации может:

- создать пост;
- удалить собственный пост;
- просмотреть комментарии;
- получить подтверждение перед удалением.

Удаление поста выполняется с каскадным удалением связанных комментариев.

### Адаптивный UI

Интерфейс поддерживает:

- светлую тему;
- тёмную тему;
- desktop;

В качестве визуального элемента используется традиционный казахский орнамент **қошқармүйіз**.

Орнамент применяется как полупрозрачный фон с использованием CSS-маскирования через `linear-gradient`.

# Технологический стек

## Backend

| Технология | Назначение |
|---|---|
| Java 17 | Основной язык |
| Spring Boot 3 | Backend framework |
| Spring Data JPA | Работа с persistence layer |
| Hibernate | ORM |
| PostgreSQL | Поддерживаемая внешняя СУБД |
| Maven | Сборка проекта |
| REST API | Взаимодействие frontend/backend |

### Почему Spring Boot?

Spring Boot предоставляет:

- готовую инфраструктуру для REST API;
- интеграцию со Spring Data JPA;
- удобную работу с транзакциями;
- поддержку валидации;
- масштабируемую архитектуру;
- удобную интеграцию с базами данных.

JPA также позволяет удобно реализовать связи между сущностями и каскадное удаление связанных данных.

---

## Frontend

| Технология | Назначение |
|---|---|
| React 18 | UI framework |
| TypeScript | Типизация |
| Vite | Dev server и build tool |
| CSS3 | Стилизация |
| CSS Custom Properties | Темизация |
| Lucide React | Иконки |

### Почему React + TypeScript + Vite?

**React** используется для построения компонентного интерфейса.

**TypeScript** обеспечивает строгую типизацию моделей и состояния приложения, например:

- `Post`
- `Comment`
- `User`
- `SubscriptionStatus`

Это позволяет обнаруживать множество ошибок ещё на этапе компиляции.

**Vite** обеспечивает быстрый development workflow благодаря:

- мгновенному запуску dev server;
- HMR (Hot Module Replacement);
- быстрой сборке production bundle.

# Основные функции

## 1. Создание публикации

Пользователь вводит текст в `textarea` и публикует его.

Поле ввода поддерживает автоматическое изменение высоты:

```text
textarea
   │
   ▼
scrollHeight
   │
   ▼
автоматическое изменение высоты
```

Это особенно полезно при вставке длинного текста, сгенерированного AI.

---

## 2. AI-генерация

AI-ассистент работает по следующему сценарию:

```text
Пользователь
     │
     ▼
AI Generator Modal
     │
     ▼
Текстовый prompt
     │
     ▼
/api/ai/generate
     │
     ▼
Gemini
     │
     ▼
Сгенерированный текст
     │
     ▼
Textarea создания поста
```

---

## 3. Лайки

Пользователь может поставить или убрать лайк непосредственно из карточки публикации.

Endpoint:

```http
POST /api/posts/{id}/like
```

---

## 4. Комментарии

Для каждого поста доступны комментарии.

Endpoint:

```http
GET /api/posts/{id}/comments
```

Создание комментария:

```http
POST /api/posts/{id}/comments
```

Комментарии сохраняют дату и время создания.

---

## 5. Подписки

Пользователь может подписаться на другого пользователя непосредственно:

- из карточки публикации;
- из профиля пользователя.

Состояние подписки отображается динамически.

Основные состояния:

```text
NOT_FOLLOWING
      │
      │ Subscribe
      ▼
FOLLOWING
      │
      │ Unsubscribe
      ▼
NOT_FOLLOWING
```

---

## 6. Переключение пользователей

Для демонстрационного режима используется `localStorage`.

Упрощённая схема:

```text
UserDropdown
     │
     ▼
select user
     │
     ▼
currentUser
     │
     ▼
localStorage
     │
     ▼
React state
     │
     ▼
UI обновляется
```

Переключение происходит без необходимости повторной авторизации.

# REST API

Основные REST endpoints проекта:

| Метод | Endpoint | Назначение |
|---|---|---|
| `GET` | `/api/posts` | Получение публикаций |
| `POST` | `/api/posts` | Создание публикации |
| `DELETE` | `/api/posts/{id}` | Удаление собственной публикации |
| `POST` | `/api/posts/{id}/like` | Поставить/убрать лайк |
| `GET` | `/api/posts/{id}/comments` | Получить комментарии |
| `POST` | `/api/posts/{id}/comments` | Добавить комментарий |
| `GET` | `/api/subscriptions` | Получение подписок |
| `POST` | `/api/subscriptions` | Создание подписки |
| `DELETE` | `/api/subscriptions/{id}` | Отмена подписки |
| `POST` | `/api/ai/generate` | AI-генерация текста |

> Точный набор HTTP-методов может зависеть от текущей реализации backend.

# Backend

Перейдите в директорию backend:

```bash
cd bailanysta-backend
```

Запустите приложение через Maven Wrapper:

### Linux / macOS

```bash
./mvnw spring-boot:run
```

### Windows

```bash
mvnw.cmd spring-boot:run
```

После запуска backend будет доступен по адресу:

```text
http://localhost:8080
```

При старте приложения `DataInitializer` автоматически создаёт начальные демонстрационные данные.

## Custom UserDropdown

Вместо стандартного:

```html

```

используется собственный React-компонент.

Преимущества:

## Казахский орнамент

Для оформления используется традиционный орнамент **қошқармүйіз**.

Фон реализован комбинацией изображения и `linear-gradient`:

```css
background-image:
    linear-gradient(
        rgba(...),
        rgba(...)
    ),
    url('/kazakh-ornament.png');
```

Альфа-канал позволяет уменьшить визуальную насыщенность орнамента без изменения исходного изображения.

Это позволяет сохранить:

- национальный визуальный стиль;
- читаемость текста;
- адаптивность;
- возможность использования одного изображения в разных темах.

## Auto-resizing Textarea

Для формы создания публикации используется ссылка на DOM-элемент:

```text
textareaRef
```

При изменении содержимого:

```text
input
  │
  ▼
textareaRef
  │
  ▼
scrollHeight
  │
  ▼
height
```

Таким образом, поле автоматически расширяется под содержимое.

Это особенно полезно для длинных AI-сгенерированных текстов.

---

## Multi-User Switch

Вместо полноценной authentication-системы используется демонстрационный механизм:

```text

```

Это позволяет мгновенно менять активного пользователя и тестировать социальные сценарии.

Например:

```text
Alice
  │
  ├── follows Bob
  │
  └── likes Bob's post

        ↓

Bob
  │
  └── видит новый лайк
```

# Принятые компромиссы (Trade-offs)

## localStorage вместо JWT/OAuth

### Решение

Для текущей версии проекта используется выбор пользователя из списка и хранение активного пользователя в `localStorage`.

### Компромисс

Это не является полноценной системой authentication/authorization.

### Причина

Основная задача проекта — демонстрация:

- UI/UX;
- социальной механики;
- AI-интеграции;
- взаимодействия между пользователями.

Полноценная authentication-система усложнила бы демонстрационный сценарий.

### Возможное развитие

В production-версии механизм может быть заменён на:

- JWT;
- OAuth 2.0;
- OpenID Connect;
- session-based authentication.

---

## H2 вместо внешней СУБД

### Решение

Для локального запуска используется H2 In-memory.

### Преимущество

Проект можно запустить практически без дополнительной инфраструктуры.

Не требуется устанавливать:

- PostgreSQL;
- отдельный DB server;
- Docker Compose.

### Компромисс

После перезапуска приложения данные базы сбрасываются.

Начальные данные создаются заново через `DataInitializer`.

Для production может использоваться PostgreSQL.

---

## CSS вместо Tailwind / UI Framework

### Решение

Стилизация реализована через чистый CSS3 и CSS Custom Properties.

### Компромисс

Необходимо вручную реализовывать:

- responsive styles;
- animations;
- theme system;
- component styles.

### Причина

Это обеспечивает полный контроль над визуальной частью приложения, включая:

- казахский орнамент;
- Dark Mode;
- кастомный dropdown;
- hover effects;
- modal animations.

# Известные проблемы и ограничения

## CORS при DELETE

Во время локальной разработки некоторые браузеры или конфигурации могут блокировать `DELETE` requests при отсутствии необходимых CORS headers.

Для решения используется глобальная CORS-конфигурация backend и/или Vite proxy.

В Spring Boot может использоваться:

```java
@CrossOrigin
```

либо глобальный:

```java
WebMvcConfigurer
```

---

## Кэширование favicon

После замены:

```text
public/logo.png
```

браузер может продолжать отображать старую favicon из cache.

Для обновления рекомендуется выполнить hard reload:

### Windows

```text
Ctrl + F5
```

### macOS

```text
Cmd + Shift + R
```

---

## `background-attachment: fixed` на мобильных устройствах

Некоторые мобильные браузеры могут ограничивать или отключать:

```css
background-attachment: fixed;
```

для снижения нагрузки на GPU и экономии заряда батареи.

В результате поведение фонового орнамента на мобильных устройствах может отличаться от desktop.

# Demo Workflow

Для демонстрации основных возможностей можно использовать следующий сценарий:

```text
1. Запустить Backend
        ↓
2. Запустить Frontend
        ↓
3. Выбрать пользователя Alice
        ↓
4. Создать публикацию
        ↓
5. Переключиться на Bob
        ↓
6. Подписаться на Alice
        ↓
7. Поставить лайк
        ↓
8. Оставить комментарий
        ↓
9. Переключиться обратно на Alice
        ↓
10. Проверить взаимодействия
        ↓
11. Использовать AI Generator
        ↓
12. Сгенерировать новый пост
        ↓
13. Отредактировать и опубликовать
```

---

# Запуск в двух терминалах

### Terminal 1 — Backend

```bash
cd bailanysta-backend
./mvnw spring-boot:run
```

### Terminal 2 — Frontend

```bash
cd bailanysta-frontend
npm install
npm run dev
```

После этого:

```text
Backend:  http://localhost:8080
Frontend: http://localhost:5173
```
